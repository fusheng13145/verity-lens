# 项目规格（Project Spec）

**目的**：定义项目定位、产品目标、用户画像与功能范围（in/out），作为需求基线。技术设计见 `design-blueprint.md`；本文只回答"做什么、为谁做、做到什么程度"。

## 1. 项目定位

面向实验室内部（1–10 人团队）的**科研全能 Agent 助手系统**：以 Agent 运行时为底座，通过工程化约束（可复现、可审计、失败闭环）让 AI 可靠地参与"文献→假设→实验→分析→写作"全流程。

## 2. 目标用户

| 用户 | 诉求 | 使用方式 |
|------|------|----------|
| 研究者（PI） | 研究加速 + 结果可信 | 主 Agent 交互、HITL 审批、预算审批 |
| 合作者 | 并行推进分支研究 | Git 假设分支、写锁、审阅 |
| 领域专家 | 方法论沉淀 | SKILL.md 编写、归因复核 |
| 工程师 | 系统可维护 | HAL/编排层/Sidecar 开发 |

## 3. 功能范围（In Scope）

- 五阶段研究生命周期编排（literature→question→experiment→analysis→writing）与门禁/HITL
- 失败驱动迭代闭环（failure_ledger、五类失败分类学、假设树 refuted/revised）
- 学科 Bundle 体系（L0/L1/L2）+ 半自动生成工厂
- 文献 RAG、DOI 校验、统计检验/功效分析、图表、脱敏、HPC 提交
- 成本管控（四级预算 + 硬阻断 + 自动降级）与沙箱安全
- Git-First 协作（假设分支、制品写锁、PR review）
- Web 前端（React + Vite + TS）：阶段看板、HITL 审批页、失败登记簿查看，对接 Headless API（对设计的扩展交互面）

## 4. 非目标（Out of Scope）

- 企业级多租户 / SaaS / SSO / 计费（评估见蓝图附录 A）
- 多人实时共享同一 Agent 会话、OT/CRDT 实时协同编辑
- 训练或自研 Agent 运行时内核（使用 DSH 等现成底座）
- 全自动无人工参与的科研产出（关键节点强制 HITL）

## 5. 成功指标

| 指标 | 目标 |
|------|------|
| 单学科端到端闭环 | Phase 1 跑通（检索→写作草稿） |
| 失败闭环可用 | METH/HYP 失败案例归因→再实验全链路走通 |
| 可复现性 | `make reproduce` 从 raw 到 figures 完全一致 |
| 引用有效性 | ≥95% DOI 可验证 |
| 新学科接入成本 | L0 骨架 ≤ 专家 1–2 天 |
| 协作事故 | 2 人并行分支无冲突事故（Phase 3） |
