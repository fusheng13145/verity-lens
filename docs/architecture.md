# 总体架构设计

**目的**：定义系统分层、核心分工与依赖收敛策略，使团队对"系统长什么样、谁依赖谁"有统一认识。本文件是模块拆分与接口设计的上位依据。

## 1. 设计原则

1. **依赖收敛**：全项目只允许 `hal/` 直接感知运行底座（DSH）。其余模块面向 HAL 抽象接口编程。
2. **文件即状态**：项目状态 = Workspace 内声明式文件。编排层无状态，崩溃即恢复。
3. **失败是一等公民**：失败必须结构化登记并走回流协议。
4. **方法论进 Schema，不进提示词**：差异可工程化部分 = 结构 + 必填字段 + 验证脚本。
5. **协作以制品为单位**：多人协作对象是文件/实验制品，不是 Agent 会话。

## 2. 分层架构

```
交互层(A)  CLI(vl) / DSH Web UI / Headless API        → 一个项目 = 一个 Workspace = 一条 Git 历史
编排层(C)  Orchestrator Lite（无状态事件处理器）        → 门禁 / 失败回流 / 预算硬阻断
适配层(H)  HAL（依赖收敛点）                            → 会话/工具/轨迹/权限/子代理/能力探测
底座层(B)  运行底座（当前：DeepSeek Harness）           → 微内核 / Session Log / 沙箱
领域层(D)  学科 Bundle（L0/L1/L2）                      → SKILL.md + 验证脚本 + 可选 MCP
侧车层(E)  Python 常驻进程                              → RAG / DOI / 统计 / 功效 / 图表 / 脱敏 / HPC
```

## 3. 核心分工矩阵

| 职责 | 归属 | 说明 |
|------|------|------|
| 模型读写文件/调工具/留痕 | 底座(B) | 原生能力 |
| 阶段门禁/失败回流/成本管控/制品协作 | 编排层(C) | 无状态，规则声明式 |
| 底座依赖收敛/版本适配/降级 | 适配层(H) | 唯一允许 import 底座 |
| 学科差异（术语/规范/验证/可视化） | 领域层(D) | 以 Skill 注入 |
| 确定性计算/长任务/外部对接 | 侧车层(E) | 经 HAL 注册 |

## 4. 依赖与耦合约束

- **唯一耦合点**：`hal/` ↔ 底座。除 `hal/` 外，任何模块 import 底座内部 API = Code Review 阻断项。
- **模块间耦合**：通过 `interfaces.md` 契约交互；编排层↔领域层靠文件约定（RESEARCH.yaml 等）；编排层↔侧车靠工具注册接口。
- **降级边界**：HAL `capabilities()` 探测特性；缺失（如 Trajectory 分叉、子代理）时显式降级，功能不报错。

## 5. 演进约束

- 底座破坏性变更 → HAL 契约测试在 CI 拦截，季度切换演练评估备选底座。
- 编排层严禁引入常驻服务与数据库（保持无状态）。
- 学科包只声明 Skill/Preset Patch/MCP，加载逻辑在编排层，不直接调用底座内核。
